Overview

Built for competitive programmers who value simplicity

Testcase Generator eliminates the friction of creating test cases for competitive programming contests. Instead of wrestling with JSON configs or manual file creation, you define your problems in a natural folder structure.

The framework handles generation, validation, solution execution, and packaging — all deterministically reproducible with a single seed value.

Features

Everything you need, nothing you don't

A focused toolkit designed to solve one problem well: generating reliable testcases for competitive programming.

Folder-Driven Structure

Your contest organization IS your configuration. Create folders for contests and problems, add a solution.cpp, and you're ready to generate. No YAML, no JSON, no XML — just a natural directory hierarchy that mirrors how you think about problems.

LLM-Powered Specs

Provide a problem screenshot or description along with solution.cpp to your LLM using PROMPT.md. Get a complete spec.py generated automatically — no manual spec writing needed.

Deterministic Output

Same spec + same seed = identical testcases, every time. Reproduce results, debug issues, and verify correctness with confidence.

Rich Strategy Library

28 built-in strategies for scalars, strings, graphs, and trees. From minimum/maximum edge cases to complex graph topologies like chains, stars, and balanced trees.

Custom Test Cases

Define your own test generators when built-in strategies aren't enough. Write a simple function, and the framework integrates it seamlessly into your test suite.

Automatic Packaging

Generates ready-to-upload ZIP files for HackerRank and similar platforms. Input/output pairs are verified and packaged automatically.

Custom Judging (Optional)

Need partial scoring or custom validation? Drop a checker.py into the problem folder — the generator validates it but keeps it out of the ZIP. Without one, HackerRank uses exact-match comparison by default.

Writing Specs

spec.py and checker.py

spec.py 
from framework import *

spec = Problem(name="Two Sum", testcases=30)

# Define input variables
N = Integer(name="N", min_value=2, max_value=100000)
A = Array(name="A", size=N, min_value=-10**9, max_value=10**9)

# Match solution.cpp read order
spec.input(N, A)

# Add test strategies
spec.add_testcases(
    minimum(), maximum(), random_case(),
    stress_case(), boundary_values(),
)

# Custom test case
def my_case(rng):
    return {"N": 5, "A": [1, 2, 3, 4, 5]}
spec.add_custom_case(my_case)

CLI

Command line interface

One command per intent. Every flag has a default, so the plain form is all most runs need.

python generate_tests.py contests/MyContest Generate all problems in a contest
python generate_tests.py contests/MyContest --problem Problem_1 Generate one problem only
python generate_tests.py contests/MyContest --dry-run Inspect specs and write nothing
python generate_tests.py contests/MyContest --report Per-case table: strategy, shape, validity
python generate_tests.py contests/MyContest --seed 999 Custom random seed (default 12345)
python generate_tests.py contests/MyContest --no-solve Generate inputs only, skip solution
python generate_tests.py contests/MyContest --timeout 10 Solution timeout in seconds (default 30)
python generate_tests.py contests/MyContest --keep Keep solution.exe after the run
python generate_tests.py contests/MyContest --verbose Per-case progress and debug logging
python generate_tests.py --help Full flag list
Naming rule: contest and problem folder names cannot contain spaces. Use MyContest, not My Contest.

Quick Start

Seven steps, no guesswork

Every step shows the exact folder, exact file name, and exact command. Follow them top to bottom.

1. Get the code onto your computer

Open a terminal (PowerShell, Command Prompt, or Bash) and run git clone https://github.com/HrishiiLit/Test-case-generator, then cd testcase-generator. You should now see generate_tests.py and a framework/ folder. If you do not have Python or a C++ compiler installed, follow every step the same way and use the Docker commands in step 5 instead of the python command.

2. Make a folder for your contest

Create one folder per contest inside contests/. Inside it, create one folder per problem. Use names without spaces (write MyContest, not My Contest).

3. Drop in your working solution

Copy the C++ file you already trust into the problem folder as solution.cpp. This file is your oracle — it produces the expected outputs for every testcase, so it must be correct.

4. Get spec.py from an AI assistant

Open PROMPT.md, copy its entire contents, then paste it into ChatGPT, Claude, Gemini, or Copilot together with two things: your problem statement (text or a screenshot of it) and the code of solution.cpp. Ask for the spec.py file back. Save the reply as spec.py in the same problem folder.

5. Run the generator

From the project root, run python generate_tests.py contests/MyContest. The tool writes the input files, runs your solution.cpp on each one to get the outputs, checks they all passed, and packs everything into a ZIP.

No Python or C++ compiler? Run it in Docker

The Docker image ships with Python and g++ already inside it, so there is nothing to install and no pip install step to worry about. Mount your project folder and everything you edit or generate stays on your computer. Get Docker Desktop (opens in a new tab)

1 Build the image once
docker build -t testcase-generator .
2 Point it at your contest folder

These two lines are identical except for the path syntax. Use the one that matches your shell.

PowerShell or Command Prompt
docker run --rm -it -v "${PWD}:/app" testcase-generator contests/MyContest
Bash, Zsh, WSL or Git Bash
docker run --rm -it -v "$PWD:/app" testcase-generator contests/MyContest
3 Add any CLI flag after the contest path
docker run --rm -it -v "${PWD}:/app" testcase-generator contests/MyContest --report
  • In Command Prompt, replace ${PWD} with %cd% — that shell has no $PWD variable.
  • -v "…:/app" maps your project folder into the container, so spec.py edits and generated ZIPs never leave your machine.
  • Changing spec.py needs no rebuild. Step 1 is only for the first run or after editing the Dockerfile itself.

6. Confirm the ZIP appeared

Look inside your problem folder. You should see Problem_1.zip plus a testcases/ folder holding the raw files (sample_input1.txt, input1.txt, output1.txt, and so on). If the run stopped with an error, re-run with --verbose to see why.

7. Upload the ZIP to HackerRank

Open your problem on HackerRank, go to the Test Cases tab, and upload the generated .zip. The full walkthrough is in the next section.

HackerRank Upload

Last mile: putting the ZIP on HackerRank

The generator already builds a platform-ready archive. You only have to hand it over.

  1. 1

    Find the file the tool created

    The ZIP is written next to your inputs, named after the problem folder. One ZIP per problem.

    contests/MyContest/Problem_1/Problem_1.zip
  2. 2

    Open the problem editor on HackerRank

    Sign in, go to your contest, click the problem, and switch to the Test Cases section. You need edit rights on the contest for this tab to appear.

  3. 3

    Upload the ZIP, do not upload the folder

    Use the upload control, pick Problem_1.zip from your computer, and wait for the progress bar to finish. HackerRank unzips it and lists your numbered test files automatically.

  4. 4

    Check the numbering and the pairing

    Open the archive and confirm the layout: input/ and output/ folders, zero-padded and index-matched (input00.txt with output00.txt, and so on). The first three indices are your sample cases; the rest are the generated test cases. Counts on both sides must match.

  5. 5

    Save, then validate against your own solution

    Hit save. Run the reference solution once against the uploaded set — if it scores full marks, the archive and the judging settings both line up and the problem is ready to publish.

  6. 6

    Need to change something later?

    Edit spec.py, re-run the generator with the same seed, and upload the fresh ZIP. Identical inputs are reproduced exactly, so re-uploading never churns your test set.

What lands in the ZIP

Problem_1.zip ├── input/ │ ├── input00.txt # sample 1 (smallest legal input) │ ├── input01.txt # sample 2 │ ├── input02.txt # sample 3 (boundary values) │ ├── input03.txt # test case 1 │ └── input12.txt # test case 10 (stress, near limits) └── output/ ├── output00.txt # produced by solution.cpp ├── output01.txt └── output12.txt
No checker? No problem. Without a checker.py, HackerRank compares contestant output to the expected output exactly. Add a checker only if you want partial credit or whitespace-tolerant matching — and note that the ZIP never contains it. The archive is test data only, so a checker has to be attached separately through the contest's custom-checker setting.
